# Coding standards

- TypeScript strict across packages  
- ESM (`"type": "module"`)  
- Prefer explicit types on public API boundaries  
- No secrets in source; demo passwords only in local seed  
- UI: follow existing Nusa visual language (Fraunces + Source Sans, warm paper ground, green accent) — avoid generic purple-gradient AI aesthetics  
- Docs: update parity + ADR when behavior changes  
- Commits: short imperative why-focused subjects  

Frontend design constraints for marketing surfaces: see user/project rules (brand-first, no hero clutter). Portal may use denser functional UI.
